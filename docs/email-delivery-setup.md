## 2. DKIM — add one TXT record (value generated by Zoho)

The DKIM public key is generated inside your Zoho account, so the exact
`p=` value comes from there (we cannot invent it, and it must not be
emailed):

1. In the **Zoho EU** admin console: **Mail > DKIM / Email Authentication**
   for `prjgenuiworkforce.co.uk`.
2. **Enable DKIM** and choose a selector, for example `zoho` (Zoho shows
   the selector name in the setup screen).
3. Zoho shows the TXT record to publish, in this shape:

   | Field | Value |
   |---|---|
   | Host / Name | `<selector>._domainkey.prjgenuiworkforce.co.uk` (in Porkbun, enter just `<selector>._domainkey`) |
   | Type | TXT |
   | Value | `v=DKIM1; k=rsa; p=<the long public key Zoho shows>` |

4. Add it in **Porkbun > prjgenuiworkforce.co.uk > DNS records**, then
   click **Verify** in Zoho.
5. Also enable in Zoho: **Return-Path alignment / SPF customisation**
   only if Zoho's screen asks for it; otherwise leave it alone.

## 3. DMARC — add one TXT record (exact value below)

First create the **dedicated DMARC reporting alias** in Zoho:
`dmarc-reports@prjgenuiworkforce.co.uk` (a mailbox or alias used only for
aggregate reports, so they never mix with normal mail). Then in Porkbun,
add:

| Field | Value |
|---|---|
| Host / Name | `_dmarc` |
| Type | TXT |
| Value | `v=DMARC1; p=none; rua=mailto:dmarc-reports@prjgenuiworkforce.co.uk; adkim=r; aspf=r; fo=1` |

- `p=none` is deliberate: it is the monitoring phase. Aggregate reports go
  to the dedicated reporting alias so you can see what is being sent and
  whether anything fails alignment.
- Reports are monitored for **a minimum of four weeks** (your instruction,
  20 October 2026), and your approval is obtained before the policy
  changes to `quarantine` and then `reject` — the first misaligned system
  email is the thing to catch before tightening.

## 5. SMTP configuration — the secure method (no passwords by email)

The platform sends through Zoho's SMTP relay:

| Setting | Value |
|---|---|
| Host | `smtp.zoho.eu` (confirm on the SMTP settings page in your Zoho account) |
| Port | `587` with STARTTLS (or `465` TLS) |
| User | the system sender mailbox, e.g. `system@prjgenuiworkforce.co.uk` |
| Password | the app-specific password — **entered by you, never by email** |

The app password is stored as a **platform secret in the hosting account
(Vercel environment variables)**, encrypted at rest, readable by the
deployment only — never in the repository, in chat, or in ordinary
email. Two ways to get it in, both without anyone else seeing it:

- **Preferred:** you are invited to the Vercel project as a member with
  **Settings access** (or you take ownership of the project per the
  ownership-transfer proposal), and you paste the app password into the
  `SMTP_PASSWORD` environment variable yourself. We never see it.
- **Interim, if the transfer is not yet done:** set it over a live screen
  share (you type, we don't look) or use a one-time secret link that
  self-destructs on first open. Plain email is excluded in every case.

Rotation: the app password can be revoked and re-created in Zoho at any
time, and the new one replaces the old in the same place it was entered —
the platform only needs a redeploy to pick it up.
